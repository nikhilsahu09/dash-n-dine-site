Behind the build

Engineering.

The work behind Dash N Dine goes beyond placing roads and buildings. The city, waypoint network, vehicle selection, and exported game all have to work together.

Technical overview

Making the pieces work together

The main engineering challenge is coordination: the city layout, waypoint network, vehicle selection, and exported build all have to behave as expected. Here are the systems I'm working on and the problems that come with them.

01 / ENVIRONMENT

Building the city

The environment is assembled from roads, sidewalks, buildings, and scene objects. Keeping the layout organized makes it easier to expand the city and test how the driving systems interact with it.

City environment · current project image

02 / NAVIGATION

Waypoints and route selection

Waypoints need meaningful connections. Picking the nearest marker isn't enough if it sends a vehicle toward the wrong street or cuts a corner. The route logic must account for the road network and the destination being requested.

Testing focuses on connections, turns, route choice, and whether the selected path actually reaches the intended location.

03 / GAMEPLAY FLOW

Garage to driving scene

The vehicle chosen in the garage needs to be the vehicle that appears in gameplay. That means checking how selection data is stored, passed between scenes, and used when the driving scene starts.

Gameplay · current project image

04 / EXPORT & DEBUGGING

Editor versus browser

A game that runs in the editor can still fail after export. The current web build has a memory-related issue, so the browser version needs further troubleshooting before it can be presented as playable.

The process is to reproduce the failure, check the relevant project settings and logs, change one thing at a time, and retest the exported build.

Development code · current project image

How I work

Test the system, not just the scene

When a feature breaks, I try to narrow the issue down: confirm what should happen, reproduce what actually happens, inspect the relevant script or scene setup, make a targeted change, and test again. That matters especially when multiple systems depend on each other.
